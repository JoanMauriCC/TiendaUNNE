3. REQUISITOS E INSTALACIÓN
--------------------------------------------------------------------------------
  Requisitos
    - Visual Studio 2022 o superior, con el desarrollo de escritorio .NET y
      .NET Framework 4.7.2.
    - SQL Server Express (o cualquier SQL Server local) y SQL Server Management
      Studio (SSMS), para correr los scripts.
    - Conexión a internet la primera vez: Visual Studio descarga solo, por
      NuGet, las librerías de gráficos (LiveCharts) y de PDF (PDFsharp/MigraDoc).

  Pasos
    1) Abrir SSMS, conectarse a la instancia local (por defecto .\SQLEXPRESS,
       con Windows Authentication) y ejecutar los scripts de la sección 7,
       EN ESTE ORDEN (Archivo > Abrir > Archivo... y F5). Son los mismos
       archivos de la carpeta Entrega/ del proyecto:
          1_CrearBaseYTablas.sql           crea la base TiendaUNNE y las 16 tablas
          2_ProcedimientosAlmacenados.sql  los 11 procedimientos almacenados
          3_DatosIniciales.sql             caja, medios de pago y comprobantes
          4_UsuariosPorPerfil.sql          un usuario por perfil (sección 5)
          5_DatosDeEjemplo.sql             OPCIONAL: productos y clientes de ejemplo
       Ninguno borra datos, y se pueden correr más de una vez sin duplicar.

    2) Revisar la cadena de conexión en TiendaUNNE\App.config:
          Data Source=.\SQLEXPRESS;Initial Catalog=TiendaUNNE;Integrated Security=True
       "Data Source" tiene que coincidir con el nombre de la instancia de SQL
       Server (si se instaló con otro nombre, hay que cambiarlo ahí).

    3) Abrir TiendaUNNE_TallerDeProgramacion2.slnx con Visual Studio, esperar a
       que restaure los paquetes y ejecutar con F5.

    4) Iniciar sesión con alguno de los usuarios de la sección 5.

  Notas
    - La aplicación, al arrancar, deja al día lo que falte: instala sola los
      procedimientos almacenados y completa los datos de la caja si no están.
    - Como el script 4 deja usuarios cargados, la aplicación no crea su
      administrador automático (DNI 00000000): usar los usuarios de abajo.
    - El archivo INSTRUCCIONES_INSTALACION.txt del proyecto describe otra forma de
      instalar, con los scripts de la raíz del repositorio y un administrador
      automático (DNI 00000000 / contraseña Admin.1234). Las dos formas sirven;
      para esta entrega alcanza con los pasos de esta sección.
    - Si da "No se pudo conectar con la base de datos": revisar que el servicio
      "SQL Server (SQLEXPRESS)" esté iniciado y el nombre de instancia de App.config.
    - Error de certificado SSL desde SSMS: en la conexión, Options >> Connection
      Properties > tildar "Trust server certificate".


4. QUÉ INCLUYE EL SISTEMA (resumen)
--------------------------------------------------------------------------------
  Arquitectura en 3 capas (Presentación / Negocio / Datos) más Entidades, sobre
  Windows Forms (C#, .NET Framework 4.7.2) y SQL Server.
    - Caja: apertura con conteo de billetes, catálogo, cliente, cobro con varios
      medios de pago, comprobantes (Ticket, Factura B, Factura A), historial de
      ventas con reimpresión, notas de crédito y cierre con arqueo.
    - Stock: reserva de unidades mientras el ticket está abierto.
    - Usuarios, Productos y Categorías (con baja lógica), Clientes.
    - Reportes de ventas, productos, recaudación y clientes, con gráficos y PDF.
    - Auditoría legible con filtros y resaltado de movimientos sensibles.
    - Backup y restauración de la base. Asistente de ventas con IA (opcional).
    - Seguridad: contraseñas con PBKDF2, roles, bloqueo a los 5 intentos fallidos.


5. USUARIOS POR PERFIL
--------------------------------------------------------------------------------
  Se ingresa con el DNI como usuario. Los crea el script 4_UsuariosPorPerfil.sql.

  Perfil           Usuario (DNI)   Contraseña        Qué puede hacer
  ---------------  --------------  ----------------  ----------------------------
  Administrador    30000001        Admin.2026        Todo: Usuarios, Productos,
                                                     Categorías, Auditoría,
                                                     Reportes, Caja, Backup y
                                                     Asistente. También emite
                                                     notas de crédito.
  Supervisor       30000002        Supervisor.2026   Caja y Reportes. También
                                                     emite notas de crédito.
  Cajero           30000003        Cajero.2026       Solo Caja: vender, cobrar,
                                                     ver el historial y
                                                     reimprimir tickets (no emite
                                                     notas de crédito).

  - Para probar la restauración de un backup (solo Administrador) se piden dos
    llaves: la contraseña del Administrador y la de otra persona Administrador o
    Supervisor (por ejemplo, el usuario Supervisor de arriba).
  - Las contraseñas no se guardan en la base: se guarda su hash (PBKDF2).
  - Un usuario se bloquea tras 5 contraseñas incorrectas seguidas; el
    Administrador lo desbloquea desde la pantalla Usuarios.


6. ASISTENTE DE IA (OPCIONAL)
--------------------------------------------------------------------------------
  La sección "Asistente" (solo Administrador) responde con Google Gemini. Sin
  configurarlo, el resto del sistema funciona igual: solo el Asistente avisa que
  falta la clave. Para activarlo:

    1) Entrar a https://aistudio.google.com/apikey con una cuenta de Google y
       tocar "Create API key" (es gratuita).
    2) Copiar la clave.
    3) En Windows: buscar "variables de entorno" > "Editar las variables de
       entorno de esta cuenta" > Variables de usuario > "Nueva...":
          Nombre:  GEMINI_API_KEY
          Valor:   (la clave copiada)
    4) Cerrar y volver a abrir Visual Studio.

  La clave NO está en el código ni en App.config (el repositorio es público):
  cada persona usa la suya.

/* =============================================================================
   TiendaUNNE - 1. Crear la base de datos y las tablas
   Taller de Programación II - UNNE
   -----------------------------------------------------------------------------
   Motor: SQL Server 2016 o superior (Express alcanza).

   Qué hace:
     - Crea la base TiendaUNNE (si no existe).
     - Crea las 16 tablas con sus claves, restricciones e índices.
     - Carga los 3 perfiles de usuario (Administrador, Supervisor y Cajero).

   Es SEGURO: no borra nada. Cada tabla se crea solo si todavía no existe, así que
   se puede correr más de una vez sin perder datos.

   Orden de ejecución de los scripts de la entrega:
     1_CrearBaseYTablas.sql           (este)
     2_ProcedimientosAlmacenados.sql
     3_DatosIniciales.sql
     4_UsuariosPorPerfil.sql
     5_DatosDeEjemplo.sql             (opcional)

   Las 16 tablas, en orden de creación (respeta las claves foráneas):
      1. Persona            9. Caja
      2. Perfil            10. Caja_sesion
      3. Usuario           11. Tipo_comprobante
      4. Cliente           12. Medio_pago
      5. Auditoria         13. Venta_cabecera
      6. Categoria         14. Venta_detalle
      7. Producto          15. Venta_pago
      8. Reserva_stock     16. Movimiento_caja
   ============================================================================= */

IF OBJECT_ID('dbo.Persona', 'U') IS NULL
BEGIN
    CREATE TABLE dbo.Persona
    (
        id_persona        INT            IDENTITY(1,1) NOT NULL,
        dni_cuit          NVARCHAR(20)   NOT NULL,   -- documento: hoy se usa solo el DNI
        nombre            NVARCHAR(100)  NOT NULL,
        apellido          NVARCHAR(100)  NOT NULL,
        direccion         NVARCHAR(200)  NULL,
        telefono          NVARCHAR(30)   NULL,
        email             NVARCHAR(150)  NULL,
        fecha_nacimiento  DATE           NULL,
        activo            BIT            NOT NULL CONSTRAINT DF_Persona_activo DEFAULT (1),

        CONSTRAINT PK_Persona PRIMARY KEY (id_persona),
        CONSTRAINT UQ_Persona_dni_cuit UNIQUE (dni_cuit),
        -- El DNI son exactamente 8 dígitos numéricos.
        CONSTRAINT CK_Persona_dni_cuit CHECK (dni_cuit NOT LIKE '%[^0-9]%' AND LEN(dni_cuit) = 8)
    );
END
GO

-- 3. Usuario  (1 a 1 con Persona). Se ingresa con el DNI de la Persona.
--    La contraseña no se guarda: se guarda su hash PBKDF2 y el salt.
-------------------------------------------------------------------------------
IF OBJECT_ID('dbo.Usuario', 'U') IS NULL
BEGIN
    CREATE TABLE dbo.Usuario
    (
        id_usuario        INT             IDENTITY(1,1) NOT NULL,
        id_persona        INT             NOT NULL,
        id_perfil         INT             NOT NULL,
        hash_password     VARBINARY(256)  NOT NULL,
        salt              VARBINARY(128)  NULL,
        debe_cambiar_pass BIT             NOT NULL CONSTRAINT DF_Usuario_cambiar_pass DEFAULT (0),
        intentos_fallidos TINYINT         NOT NULL CONSTRAINT DF_Usuario_intentos DEFAULT (0),
        bloqueado         BIT             NOT NULL CONSTRAINT DF_Usuario_bloqueado DEFAULT (0),
        ultimo_acceso     DATETIME2(0)    NULL,
        fecha_alta        DATETIME2(0)    NOT NULL CONSTRAINT DF_Usuario_fecha_alta DEFAULT (SYSDATETIME()),
        activo            BIT             NOT NULL CONSTRAINT DF_Usuario_activo DEFAULT (1),

        CONSTRAINT PK_Usuario PRIMARY KEY (id_usuario),
        CONSTRAINT UQ_Usuario_persona UNIQUE (id_persona),          -- relación 1 a 1
        CONSTRAINT FK_Usuario_Persona FOREIGN KEY (id_persona) REFERENCES dbo.Persona (id_persona),
        CONSTRAINT FK_Usuario_Perfil  FOREIGN KEY (id_perfil)  REFERENCES dbo.Perfil  (id_perfil)
    );
END
GO

-------------------------------------------------------------------------------
-- 4. Cliente  (1 a 1 con Persona)
-------------------------------------------------------------------------------
IF OBJECT_ID('dbo.Cliente', 'U') IS NULL
BEGIN
    CREATE TABLE dbo.Cliente
    (
        id_cliente        INT             IDENTITY(1,1) NOT NULL,
        id_persona        INT             NOT NULL,
        razon_social      NVARCHAR(150)   NULL,
        cuit              NVARCHAR(11)    NULL,         -- hace falta para la Factura A
        condicion_iva     NVARCHAR(30)    NOT NULL CONSTRAINT DF_Cliente_condicion_iva DEFAULT ('Consumidor Final'),
        limite_credito    DECIMAL(12,2)   NOT NULL CONSTRAINT DF_Cliente_limite_credito DEFAULT (0),
        saldo_cuenta      DECIMAL(12,2)   NOT NULL CONSTRAINT DF_Cliente_saldo_cuenta DEFAULT (0),
        observaciones     NVARCHAR(300)   NULL,
        fecha_alta        DATETIME2(0)    NOT NULL CONSTRAINT DF_Cliente_fecha_alta DEFAULT (SYSDATETIME()),
        activo            BIT             NOT NULL CONSTRAINT DF_Cliente_activo DEFAULT (1),

        CONSTRAINT PK_Cliente PRIMARY KEY (id_cliente),
        CONSTRAINT UQ_Cliente_persona UNIQUE (id_persona),          -- relación 1 a 1
        CONSTRAINT FK_Cliente_Persona FOREIGN KEY (id_persona) REFERENCES dbo.Persona (id_persona),
        CONSTRAINT CK_Cliente_limite_credito CHECK (limite_credito >= 0),
        CONSTRAINT CK_Cliente_cuit CHECK (cuit IS NULL OR (cuit NOT LIKE '%[^0-9]%' AND LEN(cuit) = 11)),
        CONSTRAINT CK_Cliente_condicion_iva CHECK (condicion_iva IN (N'Consumidor Final', N'Responsable Inscripto', N'Monotributista', N'Exento'))
    );

    -- Un CUIT no se repite entre clientes (los NULL no cuentan).
    CREATE UNIQUE INDEX UQ_Cliente_cuit ON dbo.Cliente (cuit) WHERE cuit IS NOT NULL;
END
GO

-- 5. Auditoria  (registro de altas, bajas y modificaciones)
-------------------------------------------------------------------------------
IF OBJECT_ID('dbo.Auditoria', 'U') IS NULL
BEGIN
    CREATE TABLE dbo.Auditoria
    (
        id_auditoria            BIGINT          IDENTITY(1,1) NOT NULL,
        id_usuario              INT             NULL,               -- quién ejecutó la acción
        fecha_hora              DATETIME2(3)    NOT NULL CONSTRAINT DF_Auditoria_fecha_hora DEFAULT (SYSDATETIME()),
        accion                  NVARCHAR(20)    NOT NULL,           -- ALTA / BAJA / MODIFICACION
        tabla_afectada          NVARCHAR(100)   NOT NULL,
        id_registro_afectado    INT             NULL,
        valor_anterior          NVARCHAR(MAX)   NULL,
        valor_nuevo             NVARCHAR(MAX)   NULL,

        CONSTRAINT PK_Auditoria PRIMARY KEY (id_auditoria),
        CONSTRAINT FK_Auditoria_Usuario FOREIGN KEY (id_usuario) REFERENCES dbo.Usuario (id_usuario),
        CONSTRAINT CK_Auditoria_accion CHECK (accion IN ('ALTA','BAJA','MODIFICACION'))
    );

    CREATE INDEX IX_Auditoria_fecha   ON dbo.Auditoria (fecha_hora DESC);
    CREATE INDEX IX_Auditoria_usuario ON dbo.Auditoria (id_usuario);
END

-- 8. Reserva_stock  (stock apartado por los tickets en curso; vence solo)
--    Una fila por ticket (token) y producto. Stock libre = stock - reservas vigentes.
-------------------------------------------------------------------------------
IF OBJECT_ID('dbo.Reserva_stock', 'U') IS NULL
BEGIN
    CREATE TABLE dbo.Reserva_stock
    (
        id_reserva   INT              IDENTITY(1,1) NOT NULL,
        token        UNIQUEIDENTIFIER NOT NULL,                 -- identifica el ticket en curso
        id_producto  INT              NOT NULL,
        id_usuario   INT              NOT NULL,                 -- quién tiene el ticket abierto
        cantidad     DECIMAL(12,3)    NOT NULL,
        creada       DATETIME2(0)     NOT NULL CONSTRAINT DF_Reserva_stock_creada DEFAULT (GETDATE()),
        vence        DATETIME2(0)     NOT NULL,

        CONSTRAINT PK_Reserva_stock PRIMARY KEY (id_reserva),
        CONSTRAINT UQ_Reserva_stock_token_producto UNIQUE (token, id_producto),
        CONSTRAINT FK_Reserva_stock_Producto FOREIGN KEY (id_producto) REFERENCES dbo.Producto (id_producto),
        CONSTRAINT FK_Reserva_stock_Usuario  FOREIGN KEY (id_usuario)  REFERENCES dbo.Usuario (id_usuario),
        CONSTRAINT CK_Reserva_stock_cantidad CHECK (cantidad > 0)
    );

    CREATE INDEX IX_Reserva_stock_producto ON dbo.Reserva_stock (id_producto, vence);
END

BEGIN
    CREATE TABLE dbo.Caja_sesion

        id_caja_sesion          INT            IDENTITY(1,1) NOT NULL,

-------------------------------------------------------------------------------
-- sp_ExisteEmailPersona
-- Indica si el email ya lo tiene registrado otra persona.
--
--   @email               email a buscar (llega ya recortado desde Negocio)
--   @id_persona_excluir  persona que se está editando, para que su propio email
--                        no cuente como repetido. NULL en un alta.
--
-- Devuelve una fila con la columna "existe": 1 si está repetido, 0 si no.
-- La comparación no distingue mayúsculas porque la base usa collation
-- insensible a mayúsculas: "Juan@Mail.com" y "juan@mail.com" son el mismo.
-------------------------------------------------------------------------------
IF OBJECT_ID('dbo.sp_ExisteEmailPersona', 'P') IS NOT NULL
    DROP PROCEDURE dbo.sp_ExisteEmailPersona;
GO

CREATE PROCEDURE dbo.sp_ExisteEmailPersona
    @email               NVARCHAR(150),
    @id_persona_excluir  INT = NULL
AS
BEGIN
    SET NOCOUNT ON;

    SELECT CAST(
             CASE WHEN EXISTS (
                 SELECT 1
                 FROM   dbo.Persona
                 WHERE  email = @email
                   AND  (@id_persona_excluir IS NULL OR id_persona <> @id_persona_excluir)
             )
             THEN 1 ELSE 0 END
           AS BIT) AS existe;
END
GO

-------------------------------------------------------------------------------
-- sp_DarDeBajaCategoria
-- Da de baja (baja lógica) una categoría, siempre que no tenga productos activos.
--
--   @id_categoria       categoría a dar de baja
--   @productos_activos  (salida) cuántos productos activos tiene la categoría
--   @filas              (salida) 1 si se dio de baja; 0 si no se tocó nada
--                       (tenía productos activos, ya estaba inactiva o no existe)
--
-- La cuenta de productos y el UPDATE van juntos: el bloqueo evita que otro puesto
-- agregue un producto a la categoría justo en el medio. La auditoría la graba la
-- aplicación en la misma transacción.
-------------------------------------------------------------------------------
IF OBJECT_ID('dbo.sp_DarDeBajaCategoria', 'P') IS NOT NULL
    DROP PROCEDURE dbo.sp_DarDeBajaCategoria;
GO

CREATE PROCEDURE dbo.sp_DarDeBajaCategoria
    @id_categoria       INT,
    @productos_activos  INT OUTPUT,
    @filas              INT OUTPUT
AS
BEGIN
    SET NOCOUNT ON;

    SET @filas = 0;

    SELECT @productos_activos = COUNT(*)
    FROM   dbo.Producto WITH (UPDLOCK, HOLDLOCK)
    WHERE  id_categoria = @id_categoria AND activo = 1;

    IF @productos_activos > 0
        RETURN;

    UPDATE dbo.Categoria
    SET    activo = 0
    WHERE  id_categoria = @id_categoria AND activo = 1;

    SET @filas = @@ROWCOUNT;
END
GO
-------------------------------------------------------------------------------
-- sp_DarDeBajaProducto
-- Da de baja (baja lógica) un producto, siempre que ningún ticket en curso lo tenga
-- reservado.
--
--   @id_producto  producto a dar de baja
--   @reservado    (salida) unidades que hay reservadas ahora por tickets en curso
--   @filas        (salida) 1 si se dio de baja; 0 si no se tocó nada
--                 (estaba reservado, ya estaba inactivo o no existe)
--
-- Primero se bloquea la fila del producto, igual que hace la reserva de stock: así una
-- caja que justo está agregando el producto al ticket y esta baja no se pisan.
-- Las reservas vencidas no cuentan. La auditoría la graba la aplicación en la misma
-- transacción.
-------------------------------------------------------------------------------
IF OBJECT_ID('dbo.sp_DarDeBajaProducto', 'P') IS NOT NULL
    DROP PROCEDURE dbo.sp_DarDeBajaProducto;
GO

CREATE PROCEDURE dbo.sp_DarDeBajaProducto
    @id_producto  INT,
    @reservado    DECIMAL(12,3) OUTPUT,
    @filas        INT           OUTPUT
AS
BEGIN
    SET NOCOUNT ON;

    SET @filas = 0;

    -- Bloquea el producto (si no existe, no hay nada que dar de baja).
    IF NOT EXISTS (SELECT 1 FROM dbo.Producto WITH (UPDLOCK, HOLDLOCK) WHERE id_producto = @id_producto)
    BEGIN
        SET @reservado = 0;
        RETURN;
    END

    SELECT @reservado = ISNULL(SUM(cantidad), 0)
    FROM   dbo.Reserva_stock
    WHERE  id_producto = @id_producto AND vence > GETDATE();

    IF @reservado > 0
        RETURN;

    UPDATE dbo.Producto
    SET    activo = 0
    WHERE  id_producto = @id_producto AND activo = 1;

    SET @filas = @@ROWCOUNT;
END
GO
-------------------------------------------------------------------------------
-- sp_ObtenerOCrearCliente
-- Devuelve el cliente con ese DNI; si no existe, lo crea.
--
--   Si la persona (DNI) no existe, se crea la Persona y el Cliente.
--   Si la persona ya existe (por ejemplo, es un usuario del sistema) pero todavía no
--   es cliente, solo se le agrega el Cliente: no se pisan sus datos.
--   Si ya es cliente, se devuelve el existente (y se reactiva si estaba dado de baja).
--
--   @id_cliente  (salida) id del cliente encontrado o creado
--   @creado      (salida) 1 si se creó ahora; 0 si ya existía
--
-- Se llama dentro de una transacción de la aplicación: la Persona y el Cliente se crean
-- juntos o no se crea ninguno, y la auditoría se graba en esa misma transacción.
-- Un CUIT repetido lo rechaza el índice único UQ_Cliente_cuit.
-------------------------------------------------------------------------------
IF OBJECT_ID('dbo.sp_ObtenerOCrearCliente', 'P') IS NOT NULL
    DROP PROCEDURE dbo.sp_ObtenerOCrearCliente;
GO

CREATE PROCEDURE dbo.sp_ObtenerOCrearCliente
    @dni            NVARCHAR(20),
    @nombre         NVARCHAR(100),
    @apellido       NVARCHAR(100),
    @email          NVARCHAR(150) = NULL,
    @telefono       NVARCHAR(30)  = NULL,
    @razon_social   NVARCHAR(150) = NULL,
    @cuit           NVARCHAR(11)  = NULL,
    @condicion_iva  NVARCHAR(30),
    @id_cliente     INT OUTPUT,
    @creado         BIT OUTPUT
AS
BEGIN
    SET NOCOUNT ON;
    SET XACT_ABORT ON;

    DECLARE @id_persona INT;

    SET @creado = 0;
    SET @id_cliente = NULL;

    SELECT @id_persona = id_persona
    FROM   dbo.Persona WITH (UPDLOCK, HOLDLOCK)
    WHERE  dni_cuit = @dni;

    IF @id_persona IS NOT NULL
    BEGIN
        SELECT @id_cliente = id_cliente
        FROM   dbo.Cliente WITH (UPDLOCK, HOLDLOCK)
        WHERE  id_persona = @id_persona;

        IF @id_cliente IS NOT NULL
        BEGIN
            UPDATE dbo.Cliente SET activo = 1 WHERE id_cliente = @id_cliente AND activo = 0;
            RETURN;
        END
    END
    ELSE
    BEGIN
        INSERT INTO dbo.Persona (dni_cuit, nombre, apellido, email, telefono)
        VALUES (@dni, @nombre, @apellido, @email, @telefono);

        SET @id_persona = SCOPE_IDENTITY();
    END

    INSERT INTO dbo.Cliente (id_persona, razon_social, cuit, condicion_iva)
    VALUES (@id_persona, @razon_social, @cuit, @condicion_iva);

    SET @id_cliente = SCOPE_IDENTITY();
    SET @creado = 1;
END
GO

-- sp_ReporteClientes
-- Datos del reporte de clientes entre dos fechas. El rango es [@desde, @hasta):
-- incluye @desde y no incluye @hasta. Solo cuentan las ventas emitidas (las anuladas
-- quedan afuera).
--
-- Devuelve dos resultados:
--   1) Una fila por cliente que compró: Cliente, Compras, Total gastado, Promedio por
--      compra y fecha de la Ultima compra; del que más gastó al que menos.
--   2) Una sola fila de totales: ClientesNuevos (dados de alta en el rango),
--      VentasSinCliente (consumidor final) y VentasTotales.
-------------------------------------------------------------------------------
IF OBJECT_ID('dbo.sp_ReporteClientes', 'P') IS NOT NULL
    DROP PROCEDURE dbo.sp_ReporteClientes;
GO

CREATE PROCEDURE dbo.sp_ReporteClientes
    @desde  DATETIME2,
    @hasta  DATETIME2
AS
BEGIN
    SET NOCOUNT ON;

    -- Cada tipo de comprobante tiene un "signo": 1 en una venta y -1 en una nota de crédito.
    -- Lo gastado es neto de devoluciones, y una nota de crédito no cuenta como compra.
    -- Solo figuran los clientes que compraron en el rango.
    SELECT  c.id_cliente                    AS IdCliente,
            p.apellido + N', ' + p.nombre   AS Cliente,
            COUNT(CASE WHEN tc.signo = 1 THEN 1 END)  AS Compras,
            SUM(vc.total * tc.signo)                  AS Total,
            ISNULL(SUM(vc.total * tc.signo)
                   / NULLIF(COUNT(CASE WHEN tc.signo = 1 THEN 1 END), 0), 0) AS Promedio,
            MAX(vc.fecha_hora)                        AS Ultima
    FROM        dbo.Venta_cabecera   vc
    INNER JOIN  dbo.Tipo_comprobante tc ON tc.id_tipo_comprobante = vc.id_tipo_comprobante
    INNER JOIN  dbo.Cliente          c  ON c.id_cliente = vc.id_cliente
    INNER JOIN  dbo.Persona          p  ON p.id_persona = c.id_persona
    WHERE vc.estado = 'EMITIDA' AND vc.fecha_hora >= @desde AND vc.fecha_hora < @hasta
    GROUP BY c.id_cliente, p.apellido, p.nombre
    HAVING COUNT(CASE WHEN tc.signo = 1 THEN 1 END) > 0
    ORDER BY SUM(vc.total * tc.signo) DESC, p.apellido, p.nombre;

    SELECT
        (SELECT COUNT(*) FROM dbo.Cliente
          WHERE fecha_alta >= @desde AND fecha_alta < @hasta)                      AS ClientesNuevos,
        (SELECT COUNT(*) FROM dbo.Venta_cabecera vc
           INNER JOIN dbo.Tipo_comprobante tc ON tc.id_tipo_comprobante = vc.id_tipo_comprobante
          WHERE vc.estado = 'EMITIDA' AND vc.fecha_hora >= @desde AND vc.fecha_hora < @hasta
            AND tc.signo = 1 AND vc.id_cliente IS NULL)                            AS VentasSinCliente,
        (SELECT COUNT(*) FROM dbo.Venta_cabecera vc
           INNER JOIN dbo.Tipo_comprobante tc ON tc.id_tipo_comprobante = vc.id_tipo_comprobante
          WHERE vc.estado = 'EMITIDA' AND vc.fecha_hora >= @desde AND vc.fecha_hora < @hasta
            AND tc.signo = 1)                                                      AS VentasTotales;
END
GO

-- Crea la persona y su usuario juntos. El hash y el salt llegan calculados: la contraseña
-- en claro nunca llega a la base.
CREATE PROCEDURE dbo.sp_CrearUsuario
    @dni               NVARCHAR(20),
    @nombre            NVARCHAR(100),
    @apellido          NVARCHAR(100),
    @direccion         NVARCHAR(200) = NULL,
    @telefono          NVARCHAR(30)  = NULL,
    @email             NVARCHAR(150) = NULL,
    @fecha_nacimiento  DATE          = NULL,
    @id_perfil         INT,
    @hash_password     VARBINARY(256),
    @salt              VARBINARY(128),
    @id_usuario        INT OUTPUT
AS
BEGIN
    SET NOCOUNT ON;

    DECLARE @id_persona INT;

    INSERT INTO dbo.Persona (dni_cuit, nombre, apellido, direccion, telefono, email, fecha_nacimiento)
    VALUES (@dni, @nombre, @apellido, @direccion, @telefono, @email, @fecha_nacimiento);

    SET @id_persona = SCOPE_IDENTITY();

    INSERT INTO dbo.Usuario (id_persona, id_perfil, hash_password, salt)
    VALUES (@id_persona, @id_perfil, @hash_password, @salt);

    SET @id_usuario = SCOPE_IDENTITY();
END
GO

IF OBJECT_ID('dbo.sp_ActualizarUsuario', 'P') IS NOT NULL
    DROP PROCEDURE dbo.sp_ActualizarUsuario;

-- Actualiza la persona y el perfil del usuario. Si @hash_password viene en NULL la
-- contraseña no se toca; si viene con valor, se cambia (y deja de estar pendiente de cambio).
CREATE PROCEDURE dbo.sp_ActualizarUsuario
    @id_usuario        INT,
    @id_persona        INT,
    @dni               NVARCHAR(20),
    @nombre            NVARCHAR(100),
    @apellido          NVARCHAR(100),
    @direccion         NVARCHAR(200) = NULL,
    @telefono          NVARCHAR(30)  = NULL,
    @email             NVARCHAR(150) = NULL,
    @fecha_nacimiento  DATE          = NULL,
    @id_perfil         INT,
    @hash_password     VARBINARY(256) = NULL,
    @salt              VARBINARY(128) = NULL
AS
BEGIN
    SET NOCOUNT ON;

    UPDATE dbo.Persona
    SET    dni_cuit = @dni, nombre = @nombre, apellido = @apellido,
           direccion = @direccion, telefono = @telefono, email = @email,
           fecha_nacimiento = @fecha_nacimiento
    WHERE  id_persona = @id_persona;

    UPDATE dbo.Usuario
    SET    id_perfil = @id_perfil,
           hash_password = ISNULL(@hash_password, hash_password),
           salt = ISNULL(@salt, salt),
           debe_cambiar_pass = CASE WHEN @hash_password IS NULL THEN debe_cambiar_pass ELSE 0 END
    WHERE  id_usuario = @id_usuario;
END
GO

   TiendaUNNE - 3. Datos iniciales
   Taller de Programación II - UNNE
   -----------------------------------------------------------------------------
   Ejecutar DESPUÉS de 1_CrearBaseYTablas.sql (y del 2).

   Carga lo mínimo para que el sistema pueda vender:
     - La caja (Caja 1).
     - Los medios de pago: Efectivo, Tarjeta de débito, Tarjeta de crédito y
       Transferencia.
     - Los tipos de comprobante: Ticket, Factura B, Factura A, Nota de crédito A
       y Nota de crédito B (las notas llevan signo -1: restan en reportes y caja).

   Es lo mismo que la aplicación carga sola al arrancar (si falta). Cada fila se
   inserta solo si todavía no existe, así que se puede correr más de una vez, o
   abrir la aplicación después, sin duplicar nada.
   ============================================================================= */

SET ANSI_NULLS ON;
SET QUOTED_IDENTIFIER ON;
GO

USE TiendaUNNE;
GO

-------------------------------------------------------------------------------
-- Caja
-------------------------------------------------------------------------------
IF NOT EXISTS (SELECT 1 FROM dbo.Caja)
    INSERT INTO dbo.Caja (nombre, descripcion)
    VALUES (N'Caja 1', N'Caja principal del local');
GO

-------------------------------------------------------------------------------
-- Medios de pago
-------------------------------------------------------------------------------
IF NOT EXISTS (SELECT 1 FROM dbo.Medio_pago)
    INSERT INTO dbo.Medio_pago (nombre, requiere_referencia, es_efectivo) VALUES
        (N'Efectivo',           0, 1),
        (N'Tarjeta de débito',  1, 0),
        (N'Tarjeta de crédito', 1, 0),
        (N'Transferencia',      1, 0);
GO

-------------------------------------------------------------------------------
-- Tipos de comprobante (se compara por código)
-------------------------------------------------------------------------------
INSERT INTO dbo.Tipo_comprobante (codigo, nombre, letra, signo)
SELECT v.codigo, v.nombre, v.letra, v.signo
FROM (VALUES
    (N'TKT', N'Ticket',            CAST(NULL AS CHAR(1)),  CAST( 1 AS SMALLINT)),
    (N'FB',  N'Factura B',         CAST('B'  AS CHAR(1)),  CAST( 1 AS SMALLINT)),
    (N'FA',  N'Factura A',         CAST('A'  AS CHAR(1)),  CAST( 1 AS SMALLINT)),
    (N'NCA', N'Nota de crédito A', CAST('A'  AS CHAR(1)),  CAST(-1 AS SMALLINT)),
    (N'NCB', N'Nota de crédito B', CAST('B'  AS CHAR(1)),  CAST(-1 AS SMALLINT))
) AS v(codigo, nombre, letra, signo)
WHERE NOT EXISTS (SELECT 1 FROM dbo.Tipo_comprobante t WHERE t.codigo = v.codigo);
GO

-------------------------------------------------------------------------------
-- Comprobación: tienen que salir 1 caja, 4 medios de pago y 5 comprobantes
-------------------------------------------------------------------------------
SELECT (SELECT COUNT(*) FROM dbo.Caja)             AS Cajas,
       (SELECT COUNT(*) FROM dbo.Medio_pago)       AS MediosDePago,
       (SELECT COUNT(*) FROM dbo.Tipo_comprobante) AS TiposDeComprobante;
GO

PRINT 'Datos iniciales cargados correctamente.';
GO

/* =============================================================================

   Taller de Programación II - UNNE
   -----------------------------------------------------------------------------
   Ejecutar DESPUÉS de 1_CrearBaseYTablas.sql (necesita los perfiles).

   Crea un usuario de ejemplo por cada perfil, ya activos, sin bloqueo y SIN
   obligación de cambiar la contraseña, para poder entrar y probar cada rol:

     Perfil          DNI (usuario)   Contraseña
     Administrador   30000001        Admin.2026
     Supervisor      30000002        Supervisor.2026
     Cajero          30000003        Cajero.2026

   La contraseña NO se guarda: se guarda su hash PBKDF2 (SHA-256, 150.000
   iteraciones, salt de 16 bytes, hash de 32 bytes), el mismo que calcula la
   clase Negocio\PasswordHasher.cs de la aplicación. Los valores de abajo se
   generaron con esa misma clase y se comprobaron con su método Verificar.

   Como la tabla Usuario queda con datos, la aplicación NO crea su administrador
   automático (DNI 00000000): entrar con los usuarios de arriba.

   Se puede correr más de una vez: si el DNI ya existe, no se vuelve a cargar.
   ============================================================================= */

SET ANSI_NULLS ON;
SET QUOTED_IDENTIFIER ON;
GO

USE TiendaUNNE;
GO
-------------------------------------------------------------------------------
-- Administrador: DNI 30000001   (contraseña: Admin.2026)
-------------------------------------------------------------------------------
IF NOT EXISTS (SELECT 1 FROM dbo.Persona WHERE dni_cuit = N'30000001')
    INSERT INTO dbo.Persona (dni_cuit, nombre, apellido, email)
    VALUES (N'30000001', N'Administrador', N'Demo', N'administrador@tiendaunne.com');

IF NOT EXISTS (SELECT 1 FROM dbo.Usuario u
               INNER JOIN dbo.Persona p ON p.id_persona = u.id_persona
               WHERE p.dni_cuit = N'30000001')
    INSERT INTO dbo.Usuario (id_persona, id_perfil, hash_password, salt, debe_cambiar_pass, intentos_fallidos, bloqueado, activo)
    SELECT p.id_persona,
           (SELECT id_perfil FROM dbo.Perfil WHERE nombre = N'Administrador'),
           0x10751E680962A868D75D702B08EF0E1F2A1840282CF376F960BBD06DB8E708B5,
           0x08CF6FC3B13DDE77CC2D53AAFD6ED7CA,
           0, 0, 0, 1

IF NOT EXISTS (SELECT 1 FROM dbo.Usuario u

-------------------------------------------------------------------------------
-- Cajero: DNI 30000003   (contraseña: Cajero.2026)
-------------------------------------------------------------------------------
IF NOT EXISTS (SELECT 1 FROM dbo.Persona WHERE dni_cuit = N'30000003')
    INSERT INTO dbo.Persona (dni_cuit, nombre, apellido, email)
    VALUES (N'30000003', N'Cajero', N'Demo', N'cajero@tiendaunne.com');

IF NOT EXISTS (SELECT 1 FROM dbo.Usuario u
               INNER JOIN dbo.Persona p ON p.id_persona = u.id_persona
               WHERE p.dni_cuit = N'30000003')
    INSERT INTO dbo.Usuario (id_persona, id_perfil, hash_password, salt, debe_cambiar_pass, intentos_fallidos, bloqueado, activo)

           0, 0, 0, 1

    WHERE  p.dni_cuit = N'30000003';

-------------------------------------------------------------------------------
-- Comprobación: tienen que salir los 3 usuarios, activos y sin bloqueo
-------------------------------------------------------------------------------
SELECT p.dni_cuit AS DNI, pf.nombre AS Perfil, p.apellido + N', ' + p.nombre AS Persona,
       u.activo AS Activo, u.bloqueado AS Bloqueado, u.debe_cambiar_pass AS DebeCambiarPass
FROM        dbo.Usuario u
INNER JOIN  dbo.Persona p  ON p.id_persona = u.id_persona
INNER JOIN  dbo.Perfil  pf ON pf.id_perfil = u.id_perfil
WHERE p.dni_cuit IN (N'30000001', N'30000002', N'30000003')
ORDER BY p.dni_cuit;
GO
